# `train.py` 详细说明

`train.py` 是 AmazingHand 立方体旋转强化学习任务的启动入口。它本身不定义机器人、立方体、奖励函数或 PPO 网络，而是负责把各个模块组织起来并启动测试或训练。

```text
train.py
├── asset.py      准备机器人 USD
├── env_cfg.py    定义机器人、立方体和仿真参数
├── env.py        定义动作、观测、奖励、终止和重置逻辑
└── ppo_cfg.py    定义 PPO 网络和算法超参数
```

## 1. 检查 Python 环境

```python
if importlib.util.find_spec("numpy") is None:
    raise SystemExit(...)
```

程序首先检查当前 Python 环境中是否安装了 NumPy。如果没有找到 NumPy，程序会立即退出，并提示激活 `env_isaaclab` 环境。

这里只检查 NumPy 是否存在，不会检查它的具体版本。

## 2. 命令行参数

```python
parser = argparse.ArgumentParser(
    description="AmazingHand cube rotation with Isaac Lab PPO"
)
```

### `--num_envs`

```python
parser.add_argument("--num_envs", type=int, default=2)
```

设置并行环境数量，默认为 2。当前本地调试版只允许 1 或 2 个环境：

```python
if args.num_envs not in (1, 2):
    raise ValueError(...)
```

正式大规模训练时，通常会去掉这个限制，并使用数百或数千个并行环境。

### `--max_iterations`

```python
parser.add_argument("--max_iterations", type=int, default=1000)
```

设置 PPO 的最大训练迭代次数，默认为 1000。

`ppo_cfg.py` 中定义：

```python
num_steps_per_env = 32
```

因此，每次 PPO 迭代会先让每个环境运行 32 个策略步，再使用收集到的数据更新网络。

```text
1 个环境：每次迭代收集 32 条数据
2 个环境：每次迭代收集 64 条数据
```

### `--smoke_steps`

```python
parser.add_argument("--smoke_steps", type=int, default=0)
```

用于在不进行 PPO 训练的情况下检查环境能否正常运行。

```bash
--smoke_steps 350
```

表示使用固定的零动作运行环境 350 个策略步。如果该值为 0，程序会进入正式 PPO 训练。

### `--wandb`

```python
parser.add_argument("--wandb", action="store_true")
```

加上 `--wandb` 后，RSL-RL 会把训练曲线发送到 Weights & Biases。不加该参数时，使用 RSL-RL 默认的本地日志方式。

### `--wandb_project`

```python
parser.add_argument(
    "--wandb_project",
    default="amazinghand-cube-rotation",
)
```

设置 W&B 项目名称。

```bash
--wandb --wandb_project my_cube_test
```

### Isaac Lab 通用参数

```python
AppLauncher.add_app_launcher_args(parser)
parser.set_defaults(device="cpu")
```

`AppLauncher` 会加入 Isaac Lab 的通用参数，例如：

```text
--device
--headless
--enable_cameras
```

当前默认使用 CPU，因为这个版本主要用于 1～2 个环境的本地调试。可以通过下面的参数改为 GPU：

```bash
--device cuda:0
```

```python
app_launcher = AppLauncher(args)

```

这两行会真正启动 Isaac Sim/Kit 应用。

很多 Isaac Sim、USD 和 PhysX 模块必须在 `AppLauncher` 启动之后导入，所以下面的导入语句放在 `AppLauncher` 之后：

```python
import torch

from asset import prepare_robot_usd
from env import CubeRotationEnv
from env_cfg import CubeRotationEnvCfg
```

## 4. 准备机器人 USD

```python
robot_usd = prepare_robot_usd()
```

这会调用 `asset.py` 准备训练使用的机器人资产：

```text
RL_demo/assets/AH_Right_rl.usd
```

紧接着程序会打印实际使用的 USD 路径：

```python
print(f"Robot asset: {robot_usd}")
```

## 5. 创建环境配置

```python
env_cfg = CubeRotationEnvCfg()
```

这会读取 `env_cfg.py` 中的配置，包括：

- 机器人 USD、整体位置和旋转姿态
- 立方体大小、质量和初始位置
- 仿真时间步长
- 动作缩放和电机参数
- 奖励函数权重
- 任务成功、掉落和超时条件

命令行中的环境数量和计算设备会覆盖配置文件的默认值：

```python
env_cfg.scene.num_envs = args.num_envs
env_cfg.sim.device = args.device
```

当前机器人的初始旋转也由 `env_cfg.py` 传入环境：

```python
rot=(0.7071068, 0.7071068, 0.0, 0.0)
```

该四元数表示机器人绕每个环境坐标系的 X 轴旋转 90°。

## 6. 创建训练日志目录

```python
log_dir = None
if not args.smoke_steps:
```

只有进入正式 PPO 训练时才会创建日志目录。Smoke 测试不会创建训练日志。

目录名使用训练启动时间，例如：

```text
logs/20261014_103000
```

然后将路径写入环境配置：

```python
env_cfg.log_dir = str(log_dir)
```

## 7. 创建强化学习环境

```python
env = CubeRotationEnv(cfg=env_cfg)
```

这一行会进入 `env.py`，完成下列工作：

1. 加载 AmazingHand 机器人。
2. 创建立方体。
3. 创建地面。
4. 克隆指定数量的环境。
5. 设置机器人的 `fixed_base` 世界固定锚点。
6. 初始化关节、电机目标和任务状态。
7. 启动 PhysX 仿真。

## 8. Smoke 测试模式

当 `--smoke_steps` 大于 0 时，程序进入：

```python
if args.smoke_steps:
```

先重置环境：

```python
env.reset()
```

然后循环运行指定数量的策略步：

```python
for step in range(args.smoke_steps):
```

每一步都给机器人发送 8 维零动作：

```python
torch.zeros((args.num_envs, 8), device=env.device)
```

张量形状是：

```text
(环境数量, 动作维度)
```

例如，1 个环境时的形状为 `(1, 8)`。

### 零动作不等于机器人不动

`env.py` 将策略动作转换为电机位置目标：

```python
desired = neutral_motor_rad + action_scale_rad * actions
```

当 `actions=0` 时：

```text
desired = neutral_motor_rad
```

因此，Smoke 测试中机器人仍然会朝 `neutral_motor_rad` 定义的中立姿态运动。

### `env.step()` 的返回值

```python
_, reward, terminated, truncated, extras = env.step(...)
```

- `_`：新观测值，Smoke 测试没有使用它。
- `reward`：每个环境本步获得的奖励。
- `terminated`：任务成功、立方体掉落等导致的终止。
- `truncated`：达到最大回合时间导致的终止。
- `extras`：环境额外记录的调试和训练数据。

两种重置条件被合并为：

```python
resets = terminated | truncated
```

### Smoke 日志

程序在以下情况打印状态：

- 每 50 步
- 最后一步
- 任何环境发生重置

日志字段的含义：

| 字段 | 含义 |
|---|---|
| `reward` | 所有环境的平均奖励 |
| `turn_deg` | 立方体累计有效旋转角度 |
| `z` | 立方体高度 |
| `xy_error` | 立方体相对初始位置的水平偏移 |
| `tilt` | 立方体倾斜角 |
| `motor_error` | 电机实际角度与目标角度的平均误差 |
| `resets` | 该步发生重置的环境数量 |

这些数据由 `env.py` 中的 `self.extras["log"]` 生成。

Smoke 测试完成后执行 `return`，不会继续进入 PPO 训练。

## 9. PPO 训练模式

如果 `--smoke_steps=0`，程序会加载 RSL-RL：

```python
from rsl_rl.runners import OnPolicyRunner
from isaaclab_rl.rsl_rl import RslRlVecEnvWrapper
from ppo_cfg import CubeRotationPPORunnerCfg
```

这些模块只在正式训练时导入，所以 Smoke 测试不需要初始化 PPO。

### 创建 PPO 配置

```python
agent_cfg = CubeRotationPPORunnerCfg()
agent_cfg.max_iterations = args.max_iterations
agent_cfg.device = env.device
```

`ppo_cfg.py` 中的主要参数包括：

| 参数 | 当前值 |
|---|---:|
| Actor 隐藏层 | 128, 128 |
| Critic 隐藏层 | 128, 128 |
| 激活函数 | ELU |
| 初始动作噪声 | 0.5 |
| 学习率 | `3e-4` |
| PPO Clip | 0.2 |
| 折扣因子 `gamma` | 0.99 |
| GAE 参数 `lambda` | 0.95 |
| 每轮学习 epoch | 4 |
| Mini-batch 数量 | 2 |
| 梯度范数上限 | 1.0 |

## 10. W&B 训练记录

```python
if args.wandb:
    import wandb
    agent_cfg.logger = "wandb"
    agent_cfg.wandb_project = args.wandb_project
```

如果指定了 `--wandb`，训练器会把奖励、回合长度、策略损失、价值损失和学习率等数据上传到 W&B。

这里显式导入 `wandb`，可以在开始训练前就报告未安装的错误。

## 11. RSL-RL 版本兼容

```python
rsl_version = importlib.metadata.version("rsl-rl-lib")
agent_cfg = handle_deprecated_rsl_rl_cfg(agent_cfg, rsl_version)
```

程序会读取已安装的 RSL-RL 版本，并转换已弃用的配置字段，减少不同 RSL-RL 版本之间的兼容性问题。

## 12. 保存训练配置

```python
dump_yaml(str(log_dir / "env.yaml"), env_cfg)
dump_yaml(str(log_dir / "ppo.yaml"), agent_cfg)
```

每次正式训练都会保存完整的环境和 PPO 配置：

```text
logs/时间/env.yaml
logs/时间/ppo.yaml
```

这样可以在以后确认某个训练结果对应的机器人姿态、奖励权重、网络结构和学习率。

## 13. 包装 Isaac Lab 环境

```python
wrapped_env = RslRlVecEnvWrapper(env, clip_actions=1.0)
```

`CubeRotationEnv` 使用 Isaac Lab 的环境接口，`OnPolicyRunner` 则需要 RSL-RL 格式的接口。该包装器负责：

- 转换环境接口
- 整理观测和奖励张量
- 传递终止和超时状态
- 将策略动作限制到 `[-1, 1]`

`env.py` 内部也会对动作进行 `clamp(-1, 1)`，因此这里相当于在进入环境前再做一次保护。

## 14. 创建 PPO Runner

```python
runner = OnPolicyRunner(
    wrapped_env,
    agent_cfg.to_dict(),
    log_dir=str(log_dir),
    device=agent_cfg.device,
)
```

`OnPolicyRunner` 负责完整的 PPO 数据收集和网络更新：

1. Actor 根据 38 维观测生成 8 维动作。
2. 动作被发送给机器手的 8 个电机。
3. 环境执行物理仿真。
4. 环境返回新观测、奖励和终止状态。
5. Runner 收集每个环境的 32 个策略步。
6. 计算回报和优势函数。
7. 更新 Actor 和 Critic 网络。
8. 记录训练指标并定期保存模型。

## 15. 开始训练

```python
runner.learn(
    num_learning_iterations=agent_cfg.max_iterations,
    init_at_random_ep_len=False,
)
```

`num_learning_iterations` 来自 `--max_iterations`。

`init_at_random_ep_len=False` 表示训练开始时，所有环境都从回合第 0 步开始。设为 `True` 可以让环境从随机的回合进度开始，但当前 1～2 个环境的调试版使用 `False` 更方便观察。

## 16. 关闭环境和 Isaac Sim

内层清理：

```python
finally:
    env.close()
```

无论训练正常结束、Smoke 测试返回，还是中间抛出异常，都会关闭强化学习环境。

最外层清理：

```python
if __name__ == "__main__":
    try:
        main()
    finally:
        simulation_app.close()
```

这会确保 Isaac Sim 最终被关闭，并释放 PhysX、USD Stage、张量、窗口和渲染资源。

## 17. 完整执行流程

```text

        ↓

           ↓
```


## 19. 后续修改位置

- 更换机器人或 USD 处理方式：修改 `asset.py`。
- 修改立方体、机器人位姿和奖励权重：修改 `env_cfg.py`。
- 修改动作、观测、奖励函数或终止条件：修改 `env.py`。
- 修改 PPO 网络、学习率或采样长度：修改 `ppo_cfg.py`。
- 修改启动方式、命令行参数和日志逻辑：修改 `train.py`。
